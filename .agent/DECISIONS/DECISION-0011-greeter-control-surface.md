# DECISION-0011 — expand the greeter control surface (3 tiers) with help + an `--expert` gate

**Status:** Binding
**Date:** 2026-06-27
**Ratified:** 2026-06-27
**Project:** door
**Relates to:** D-0010 (door-theme schema + door-settings editor) — extends it; D-0006 (iced).

## Context

M4's greeter look is driven by `door-theme::Theme` (TOML + `door-settings`). A sweep
found ~70 hardcoded shader/UI constants that *could* be controls (logged in
`.agent/IDEAS/greeter-control-surface.md`). The owner ratified building all three
tiers (Tier 1 user-facing, Tier 2 power-user, Tier 3 internal), gating the most
internal behind an `--expert` flag, with sensible labels and per-control help.

## Decision

**Add ~20 new themeable controls across sky / spinner / card / behavior**, every one
defaulting to the current value so the out-of-box look is unchanged.

- **Schema:** flat `Theme` fields (consistent with the existing hand-rolled pattern,
  Principle 8), with `merge_f32`/`merge_bool` helpers to keep the merge/render
  functions terse. Per-variant keys (`sky_glow`, `error_color`, `comet_color`) live
  in `[day]` too; shared keys live once at the top level.
- **Shaders:** new controls reach the WGSL via packed uniform `vec4`s
  (`params2`/`params3` on the sky, `params2` on the spinner) — the previously
  hardcoded constants now read from uniforms. A `naga` dev-dep + tests
  parse-and-validate both shaders (no GPU), so a WGSL typo fails tests rather than
  panicking on the login screen.
- **Settings UX:** five tabs (Colors / Sky / Spinner / Card / Behavior); a **Help**
  toggle reveals a one-line description under each control; an **Advanced** toggle
  (seeded by the `--expert` CLI flag) discloses the Tier-3 controls. Patterns taken
  from halloy (optional-help wrapper) and sniffnet (CLI-flag-into-state disclosure).

## Consequences

- `door-theme/src/lib.rs`: ~20 fields on `Theme`/`ThemeFile`/`DayFile` + merge/render
  wiring; `door-theme/src/skyshader.rs`: uniform packing + `day_sky`/`cloud_layer`
  WGSL + the validation tests; `door-greeter/src/app.rs`: card/clock/fade/error
  wiring + a `status_error` flag; `door-settings/src/main.rs`: the five-tab UI, help
  + expert toggles, and the new messages/handlers.
- `dist/door/greeter.toml` documents every new key (all optional).
- Defaults reproduce today's look exactly; this is additive and reversible per key.
- A distinct `comet_color` fixes the prior nit where the background sky comet reused
  the card spinner's color.
- Follow-up (2026-06-27): the spinner orbit is pulled in (R 0.36→0.30) with a tighter
  glow and a **radial** edge-fade (a circle, never a square), so the orbiting light
  reads as a free-floating spinner rather than something happening inside a box. Added
  an optional per-variant **`logo_box`** backdrop tile (+ shared `logo_box_radius`)
  behind the logo/spinner, **transparent by default** (invisible) — controls live
  under "Logo" in the Colors tab.
- Follow-up (2026-06-27): a **preset system** — `door-settings` loads/saves whole
  day+night themes as `.toml` files (`Theme::parse_pair` / `render_pair`), scanning
  `~/.config/door/presets` + `/usr/share/door/presets` (+ `DOOR_PRESETS_DIR`). Ships
  three built-ins generated by `examples/gen_presets.rs` (regenerable, parse-tested):
  **Tokyo Night** (the default), **Supernova**, **Nebula**. To make the latter two
  actually recolor the sky, the night/day **`glow_color`** is now themeable (was a
  hardcoded indigo/sky-blue), so `sky_glow` recolors the whole atmosphere.
